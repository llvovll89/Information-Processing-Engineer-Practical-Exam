08

CPU 스케줄링 계산의 출발점

프로세스마다 도착시간, CPU 실행시간, 남은시간, 최초 실행시간, 완료시간을 기록한다. 반환시간은 도착부터 완료까지, 응답시간은 도착부터 처음 CPU를 받기까지, 대기시간은 준비 큐에서 기다린 시간이다. I/O 없는 단일 CPU 문제에서는 대기=반환-실행으로 계산한다.

비선점은 실행 중 작업을 완료·자발적 대기 전까지 빼앗지 않고 선점은 더 우선인 작업 도착·시간 할당 만료 등으로 교체한다. FCFS는 도착순, SJF는 현재 준비 작업 중 실행시간 최솟값, SRT는 남은시간 최솟값이다.

09

RR·HRN·기아·에이징

RR은 준비 큐에서 한 작업을 시간 할당량 q만큼 실행하고 남았으면 뒤에 넣는다. 할당량이 너무 작으면 문맥 교환 비용, 너무 크면 FCFS와 비슷해지는 영향을 살핀다. 같은 시각의 도착과 재삽입은 문제의 큐 처리 조건을 따른다.

HRN은 (대기+서비스)/서비스의 큰 값부터 고르는 비선점 방식으로 오래 기다린 작업의 우선순위가 올라간다. 기아는 낮은 우선 작업이 계속 밀리는 현상이고 에이징은 대기시간에 따라 우선순위를 올리는 해결 기법이다.

과정으로 이해하기

  1. 모두 도착0, A 실행5·B 실행3, q=2, 교환비용0: A0~2 B2~4 A4~6 B6~7 A7~8.
  2. 완료 A8,B7. 대기 A=8-5=3, B=7-3=4. 평균3.5.

답을 가리고 확인

HRN에서 대기6·서비스3의 우선순위는?

확인 답안 보기

(6+3)/3=3.

꼭 기억할 것

RR은 큐 회전, HRN은 큰 비율 우선, 에이징은 오래 기다린 작업 배려.

헷갈리는 지점 문맥 교환 시간이 0인지 주어졌는지 확인한다. 기아와 교착은 다른 현상이다.

10

FIFO·LRU·OPT 페이지 교체 추적표

페이지 참조를 왼쪽부터 하나씩 읽으며 프레임에 있으면 적중, 없으면 부재다. 빈 프레임에 처음 올리는 것도 부재다. FIFO는 들어온 순서를, LRU는 마지막 사용 시점을 기록한다. OPT는 미래에 가장 늦게 다시 쓰거나 다시 쓰지 않을 페이지를 내보낸다.

프레임 3개, 참조 1,2,3,1,4,2를 비교한다. FIFO는 두 번째 1에서 들어온 순서를 바꾸지 않지만 LRU는 1을 가장 최근으로 바꾼다. 이 차이가 4가 들어올 때 교체 대상을 바꾼다.

11

페이징·주소 변환·단편화

페이징은 가상 메모리와 물리 메모리를 같은 크기의 페이지·프레임으로 나눈다. 가상 주소는 페이지 번호와 페이지 내 오프셋으로 나누고 페이지 테이블에서 프레임 번호를 찾는다. 물리 주소는 프레임 번호×페이지 크기+오프셋이다. TLB는 최근 주소 변환 정보를 캐시한다.

세그먼테이션은 코드·데이터 같은 의미 단위로 가변 크기를 할당한다. 내부 단편화는 할당 공간 안의 낭비, 외부 단편화는 공간이 작은 조각으로 흩어져 연속 할당이 어려운 것이다. 스래싱은 페이지 부재·교체가 과도해 실제 작업이 줄어드는 현상이다.

과정으로 이해하기

  1. 페이지 크기 1024, 가상 주소2500 → 페이지2, 오프셋452.
  2. 페이지2가 프레임5라면 물리주소5×1024+452=5572.

12

교착·안전 상태·세마포어

교착상태는 작업들이 서로 가진 자원을 기다려 더 이상 진행하지 못하는 상태다. 상호배제·점유대기·비선점·환형대기 네 조건이 모두 필요하다. 예방은 조건 하나를 깨는 정책이고 회피는 요청을 승인해도 안전 순서가 남는지 확인한다.

은행가 알고리즘에서 Need=Max-Allocation이다. 가용 자원으로 어떤 작업의 Need를 충족하면 그 작업을 완료시키고 보유 자원을 반환했다고 가정해 다음 작업을 찾는다. 모든 작업 완료 순서를 찾으면 안전하다. 세마포어 wait(P)는 진입 가능 자원을 기다리고 signal(V)은 자원을 돌려주거나 대기 작업을 깨운다.

과정으로 이해하기

  1. 자원1종, Available=1, A Allocation1·Max2 → Need1, B Allocation1·Max3 → Need2.
  2. A 먼저 완료 가능. A의 1 반환 → Available2. 이어 B 완료. 안전 순서 A→B.

13

디스크 이동량·파일·UNIX 권한·RAID

SSTF는 현재 헤드와 가장 가까운 요청을 먼저 처리한다. SCAN은 한 방향으로 디스크 끝까지 갔다가 반대 방향으로 처리하며 LOOK은 그 방향의 마지막 요청에서 돌아온다. C-SCAN은 한 방향 처리 후 반대쪽 끝으로 돌아가고 C-LOOK은 요청 경계 기준으로 순환한다.

파일 권한 r=4,w=2,x=1을 합쳐 소유자·그룹·기타 세 자리로 표시한다. 754는 소유자 rwx, 그룹 r-x, 기타 r--다. RAID 0은 분산 기록, 1은 미러, 5는 분산 패리티 1개 장애 대응, 6은 이중 패리티 2개 장애 대응이다.

과정으로 이해하기

  1. 헤드50, 요청10·40·90의 SSTF: 50→40→10→90.
  2. 이동량10+30+80=120.
  3. 동일 크기 N개 RAID5 가용 용량=(N-1)×디스크용량, RAID6=(N-2)×용량(통상 구성).

답을 가리고 확인

권한 640은?

확인 답안 보기

소유자 rw-, 그룹 r--, 기타 ---.

꼭 기억할 것

이동량은 인접 방문 위치 차이 절댓값의 합. chmod 754 → rwxr-xr--.

헷갈리는 지점 SCAN과 LOOK의 회전 위치가 다르다. 디스크 끝 번호·방향·복귀 이동 포함 여부를 확인한다.
