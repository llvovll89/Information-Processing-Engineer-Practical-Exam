03

서브넷의 기본

IPv4는 32비트. /p의 주소 수는 2^(32-p). 보통의 서브넷에서 호스트 수는 전체-2다. 네트워크 주소는 IP AND 마스크, 브로드캐스트는 호스트 비트 전부 1이다.

답을 가리고 확인

손으로 계산하는 예

계층·캡슐화·주소·포트

송신 측은 응용 데이터를 전송 계층 정보, IP 정보, 링크 계층 정보로 감싸며 수신 측은 역순으로 해석한다. 전통적으로 전송 TCP 단위는 세그먼트, UDP는 데이터그램, 네트워크는 패킷, 링크는 프레임, 물리는 비트다.

MAC은 링크의 전달 대상, IP는 네트워크와 호스트 주소, 포트는 호스트 안의 통신 서비스를 구별한다. 라우터는 목적지 IP로 다음 경로를 고르며 링크마다 프레임의 MAC 주소는 달라질 수 있다.

TCP 연결·흐름 제어·혼잡 제어

TCP 연결 시작은 클라이언트 SYN, 서버 SYN+ACK, 클라이언트 ACK다. 순서 번호는 바이트 흐름의 순서를 표시하고 확인 응답은 수신 확인을 알린다. 재전송으로 손실에 대응하고 수신자는 윈도 크기를 알려 받아들일 양을 조절한다.

흐름 제어는 수신자가 처리할 수 있는 속도에 맞추는 것이고 혼잡 제어는 네트워크의 과도한 트래픽을 줄이는 것이다. Slow Start는 혼잡 윈도를 단계적으로 키워 경로 상태를 살피고 혼잡 회피는 증가를 조절한다.

과정으로 이해하기

  1. 수신 버퍼 부족에 따라 전송량 감소 → 흐름 제어.
  2. 경로 혼잡·손실 신호에 따라 전송량 조절 → 혼잡 제어.

DNS·DHCP·ARP·ICMP와 포트

DNS는 이름을 주소 등 레코드로 해석한다. DHCP는 IP·마스크·기본 게이트웨이 등의 설정을 제공하며 전형적인 과정은 Discover→Offer→Request→ACK다. ARP는 같은 링크에서 IPv4 주소에 대응하는 MAC 주소를 알아낸다. ICMP는 오류 알림·진단이며 ping이 사용한다.

원격 네트워크에 보낼 때 ARP로 원격 서버 MAC을 직접 찾는 것이 아니라 다음 홉인 게이트웨이의 MAC을 찾는다. IPv6는 ARP 대신 Neighbor Discovery를 사용한다.

서브넷 /23·VLSM·호스트 수 역산

프리픽스 /p는 앞 p비트가 네트워크 부분이라는 뜻이다. /23은 마스크 255.255.254.0으로 세 번째 옥텟이 2씩 나뉜다. 192.168.5.77/23은 세 번째 값 5가 4~5 구간에 있으므로 네트워크 192.168.4.0, 브로드캐스트 192.168.5.255다.

일반 IPv4 서브넷에서 H개 호스트가 필요하면 2^h-2≥H인 가장 작은 h를 찾고 /32-h로 계산한다. 50명에는 h=6, /26이 필요하다. VLSM은 필요 크기에 따라 다른 프리픽스를 배정하며 큰 블록부터 주소 정렬 경계에 맞추면 관리가 쉽다.

과정으로 이해하기

  1. 192.168.5.77/23에서 32-23=9 호스트 비트, 전체 512주소.
  2. 세 번째 옥텟 4~5, 마지막 0~255.
  3. 사용 가능한 범위 192.168.4.1~192.168.5.254, 510개.

확인 답안 보기

/25. 7 호스트 비트로 128주소 중 126호스트.

꼭 기억할 것

50호스트→64주소 블록→/26→사용 가능 62. 네트워크·브로드캐스트는 제외.

헷갈리는 지점 /31 점대점·/32 등의 예외 조건에서는 -2 공식을 무조건 쓰지 않는다.

13

라우팅·IPv6·오류 검출

RIP는 거리 벡터로 홉 수를 사용하며 최대 유효 홉 수 15, 16은 도달 불가다. OSPF는 링크 상태 정보를 바탕으로 최단 경로를 계산하고 BGP는 AS 사이 경로 정보를 교환하는 경로 벡터다. 라우팅 테이블에서 가장 구체적인 목적지 프리픽스를 우선하는 최장 프리픽스 매칭을 익힌다.

IPv6는 128비트로 16진수 그룹을 콜론으로 구분한다. ::로 연속된 0 그룹을 압축할 수 있지만 한 주소에서 한 번만 쓴다. 유니캐스트·멀티캐스트·애니캐스트를 사용하며 브로드캐스트는 없다. CRC는 XOR 다항식 나눗셈으로 오류를 검출한다.

과정으로 이해하기

  1. 목적지와 /16, /24 경로 둘 다 일치하면 /24 우선.
  2. 데이터 1101에 생성 다항식 1011(차수3)을 사용: 000을 붙여 1101000을 XOR 나눗셈하면 나머지 001, 전송 비트 1101001.

애니캐스트.

꼭 기억할 것

IPv4 32비트 / IPv6 128비트. CRC는 검출, 해밍 코드 등은 조건에 따라 정정도 가능.

헷갈리는 지점 CRC를 암호화나 악의적 변조 인증으로 설명하지 않는다.
