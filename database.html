03

함수 종속과 정규화

X→Y는 X 값이 같으면 Y도 같다는 뜻이다. 1NF는 원자값, 2NF는 후보키의 일부에 대한 비주요 속성의 부분 종속 제거, 3NF는 비주요 속성의 이행 종속 제거를 핵심으로 이해한다.

과정으로 이해하기

  1. 복합키를 먼저 표시한다. 비주요 속성이 키 전체·일부 중 어디에 종속되는지 확인한다.
  2. 일부에 종속하면 2NF로 분리한다. 비주요 속성을 거쳐 종속하면 전형적인 3NF로 분리한다.
  3. 분리 후 원래 정보를 조인으로 복원 가능한지 확인한다.

이행 함수 종속.

꼭 기억할 것

복합키 (학번,과목)에서 학번→학생이름은 부분 종속. 학번→학과코드→학과명은 이행 종속의 전형.

헷갈리는 지점 3NF의 엄밀 조건: 모든 비자명 X→A에서 X가 슈퍼키이거나 A가 주요 속성. 주요 속성은 어떤 후보키에라도 포함되는 속성이다.

04

07

08

ER 모델·개체·속성·관계

개체는 관리하려는 대상(학생·과목), 속성은 대상의 특성(학번·이름), 관계는 대상 사이의 연관(수강)이다. 개념 설계에서 ER 모델을 만들고 논리 설계에서 테이블·키로 바꾼다.

1:N은 보통 N쪽 테이블에 1쪽의 키를 외래키로 둔다. M:N은 관계를 별도 연결 테이블로 만들고 양쪽 키를 저장한다. 예를 들어 학생-과목의 수강 관계는 수강(학번,과목번호,성적)으로 표현한다.

과정으로 이해하기

  1. 학생(학번 PK,이름), 과목(과목번호 PK,과목명)을 만든다.
  2. 수강에 학번·과목번호를 외래키로 두고, 둘을 복합 기본키로 삼을 수 있다.

확인 답안 보기

꼭 기억할 것

개체→테이블 / 속성→열 / 관계→외래키·연결 테이블. 식별자와 참여 조건도 확인한다.

09

후보키의 유일성·최소성 찾기

슈퍼키는 모든 행을 구별할 수 있는 속성 집합이다. 후보키는 슈퍼키 중 어느 속성도 빼지 못하는 최소 집합이다. 학번만으로 학생을 구별하면 {학번,이름}도 슈퍼키지만 후보키는 아니다. 학번을 남기고 이름을 빼도 구별되기 때문이다.

함수 종속으로 후보키를 찾을 때 X의 속성 폐포 X+를 구한다. 시작 X에 X로 결정 가능한 속성을 계속 추가하고 전체 속성을 얻으면 X는 슈퍼키다. 그 뒤 불필요한 속성을 제거해 최소성을 확인한다.

과정으로 이해하기

  1. R(A,B,C), A→B, B→C라면 A+={A,B,C}. A는 후보키.
  2. AB+도 전체지만 A만으로 충분하므로 AB는 후보키가 아니다.

답을 가리고 확인

이메일과 학번이 각각 유일하고 둘 다 후보키라면 학번을 기본키로 정했을 때 이메일은?

확인 답안 보기

대체키. 선택되지 않은 후보키다.

꼭 기억할 것

후보키 = 유일성 + 최소성. 최소성은 “속성 개수가 가장 작다”와 다르다.

헷갈리는 지점 서로 다른 후보키의 속성 개수가 달라도 둘 다 최소성을 만족할 수 있다.

10

이상 현상과 1NF→2NF→3NF 분해

한 테이블에 서로 다른 대상을 섞으면 중복 때문에 삽입·삭제·갱신 이상이 생긴다. 수강 행이 없으면 학생 정보도 저장할 수 없는 것이 삽입 이상, 마지막 수강을 지우며 학생 정보를 잃는 것이 삭제 이상, 학생 이름을 여러 행 중 일부만 바꾸는 것이 갱신 이상이다.

수강(학번,과목,학생이름,학과코드,학과명,성적)의 키가 (학번,과목)일 때 학번→학생이름,학과코드는 부분 종속이다. 이를 학생 테이블로 분리하면 2NF다. 학생에서 학과코드→학과명을 별도 학과 테이블로 분리하면 전형적인 3NF다.

삭제 이상마지막 수강 삭제로 학생 이름도 사라짐
갱신 이상동일 학생 이름이 행마다 다르게 남음

과정으로 이해하기

  1. 수강(학번,과목,성적): 성적은 복합키 전체에 종속.
  2. 학생(학번,학생이름,학과코드): 학번이 학생 정보를 결정.
  3. 학과(학과코드,학과명): 학과명 중복 갱신을 제거.

확인 답안 보기

부분 함수 종속. 2NF에서 분리한다.

꼭 기억할 것

1NF 원자값 / 2NF 부분 종속 제거 / 3NF 비주요 속성의 이행 종속 제거.

헷갈리는 지점 정규화는 단순히 테이블을 작게 나누는 것이 아니라 종속성과 정보 보존을 고려한다.

11

BCNF·4NF·5NF와 반정규화

BCNF는 모든 비자명 함수 종속 X→Y의 X가 슈퍼키여야 한다. 주요 속성 예외가 있는 3NF보다 강하다. 4NF는 비자명 다치 종속의 결정자가 슈퍼키여야 하고 5NF는 후보키로 설명되지 않는 조인 종속을 제거한다.

학생의 취미와 사용 언어가 서로 독립인데 한 표에 조합을 모두 기록하면 학생→→취미, 학생→→언어의 다치 종속을 살핀다. 학생-취미, 학생-언어로 분리하는 것이 전형적인 4NF 학습 사례다. 반정규화는 성능을 위해 중복·병합 등을 의도적으로 도입한다.

과정으로 이해하기

  1. 학생 A의 취미 2개, 언어 3개를 독립 조합하면 6행.
  2. 두 테이블로 분리하면 취미 2행, 언어 3행으로 독립 정보를 저장한다.

답을 가리고 확인

성능을 위해 중복 열을 의도적으로 추가하는 설계는?

확인 답안 보기

반정규화(역정규화).

꼭 기억할 것

BCNF 함수 종속 / 4NF 다치 종속 / 5NF 조인 종속.

헷갈리는 지점 반정규화가 무결성을 자동 보장하는 것은 아니다. 중복 갱신·일관성 유지가 필요하다.

12

병행 제어·격리 수준·잠금

동시에 같은 데이터를 바꾸면 한 변경이 다른 변경을 덮는 갱신 손실이 생길 수 있다. 로킹은 접근을 잠금으로 조정한다. 공유 잠금은 읽기, 배타 잠금은 쓰기에 사용한다. 2PL은 잠금을 얻는 확장 단계 뒤 잠금을 풀기만 하는 축소 단계로 나눈다.

Read Uncommitted·Read Committed·Repeatable Read·Serializable은 격리 수준이다. 전통적인 표준 구분에서 Read Committed는 Dirty Read를 막고, Repeatable Read는 같은 행의 반복 읽기 변화도 막으며, Serializable은 직렬 실행에 대응하는 결과를 보장한다. 실제 DBMS의 구현은 표보다 강하거나 다를 수 있다.

과정으로 이해하기

  1. T1이 잔액 100을 읽고 T2도 100을 읽는다.
  2. T1은 10을 더해 110, T2는 20을 더해 120으로 덮으면 최종 130이 되지 않는 갱신 손실.

답을 가리고 확인

같은 조건으로 다시 조회할 때 새 행이 추가되어 보이는 현상은?

확인 답안 보기

Phantom Read(팬텀 읽기).

꼭 기억할 것

Dirty Read 미커밋 값 / Non-repeatable Read 같은 행의 값 변화 / Phantom 같은 조건의 행 집합 변화.

헷갈리는 지점 2PL은 직렬 가능성을 위한 기법이지만 교착상태가 생길 수 있다.

13

로그·UNDO·REDO·관계대수와 분산 DB

장애 복구에서는 트랜잭션의 커밋 여부와 로그 정책을 본다. 일반적인 학습 모형에서 미커밋 변경은 UNDO로 취소하고 필요한 커밋 변경은 REDO로 다시 적용한다. WAL은 데이터 페이지를 기록하기 전에 해당 로그를 먼저 영속화하는 원칙이다. 체크포인트는 복구 작업 범위를 줄인다.

관계대수는 결과를 릴레이션으로 만드는 절차적 연산이다. 선택 σ는 행 조건, 추출 π는 열, 조인은 연결, 디비전 ÷는 모든 대상과 관련된 대상을 찾는다. 분산 DB의 위치·분할·복제 투명성은 사용자가 분산 저장 세부를 의식하지 않게 하는 성질이다.

과정으로 이해하기

  1. 수강={(A,DB),(A,OS),(B,DB)}, 필수={(DB),(OS)}.
  2. 수강 ÷ 필수의 결과는 A: 두 필수 과목을 모두 수강.

위치 투명성.
