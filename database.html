핵심 규칙을 설명하고, 연습문제의 답과 이유를 해설 없이 적을 수 있으면 체크하세요. 이해 체크와 정답 기록은 별도로 저장됩니다.

01

관계 모델과 키

튜플은 행, 속성은 열, 도메인은 값의 범위, 차수(Degree)는 열 수, 카디널리티는 행 수다. 슈퍼키는 유일성, 후보키는 유일성+최소성, 기본키는 선택한 후보키, 대체키는 나머지 후보키다.

꼭 기억할 것

최소성은 속성을 하나라도 빼면 더 이상 유일하게 식별하지 못한다는 뜻이다.

헷갈리는 지점 슈퍼키가 모두 후보키는 아니다. 외래키는 중복 가능하며 NOT NULL이 없다면 NULL이 허용될 수 있다.

02

무결성과 설계 단계

개체 무결성은 기본키의 중복·NULL 금지, 참조 무결성은 외래키와 참조 대상의 일관성, 도메인 무결성은 값의 허용 범위·형식이다. 설계는 요구 분석 → 개념 → 논리 → 물리 → 구현으로 구분한다.

꼭 기억할 것

개념 설계는 ER 모델, 논리 설계는 관계 스키마, 물리 설계는 저장 구조·접근 경로를 구체화한다.

헷갈리는 지점 성능을 위해 중복을 허용하는 반정규화는 일관성 유지 비용을 키울 수 있다.

03

함수 종속과 정규화

X→Y는 X 값이 같으면 Y도 같다는 뜻이다. 1NF는 원자값, 2NF는 후보키의 일부에 대한 비주요 속성의 부분 종속 제거, 3NF는 비주요 속성의 이행 종속 제거를 핵심으로 이해한다.

꼭 기억할 것

복합키 (학번,과목)에서 학번→학생이름은 부분 종속. 학번→학과코드→학과명은 이행 종속의 전형.

헷갈리는 지점 3NF의 엄밀 조건: 모든 비자명 X→A에서 X가 슈퍼키이거나 A가 주요 속성. 주요 속성은 어떤 후보키에라도 포함되는 속성이다.

04

BCNF와 분해

BCNF는 모든 비자명 함수 종속의 결정자가 슈퍼키여야 한다. 3NF보다 강하다. 흔히 “모든 결정자가 후보키”로 암기하지만 정확한 판정은 슈퍼키 조건이다.

꼭 기억할 것

R(학생,과목,교수), (학생,과목)→교수, 교수→과목이면 후보키 (학생,과목),(학생,교수). 3NF는 가능하지만 교수는 슈퍼키가 아니므로 BCNF 위반.

헷갈리는 지점 정규형을 묻는다면 만족하는 가장 높은 단계를 답한다. 무손실 분해와 종속성 보존은 서로 다른 성질이다.

05

ACID와 동시성

원자성은 전부 성공 또는 취소, 일관성은 제약 유지, 격리성은 동시에 실행되어도 정해진 격리 수준의 관찰 보장, 지속성은 커밋 결과 유지다.

꼭 기억할 것

Dirty Read는 미커밋 데이터 읽기, Non-repeatable Read는 같은 행 재조회 값 변화, Phantom Read는 같은 조건의 행 집합 변화.

헷갈리는 지점 격리 수준마다 허용 현상이 다르다. 모든 트랜잭션이 항상 완벽한 직렬 실행처럼 보인다고 일반화하지 않는다.

06

회복·병행 제어·관계대수

로그 기반 회복은 UNDO로 미완료 변경을 취소하고 REDO로 필요한 완료 변경을 다시 반영한다. 체크포인트는 회복 시 확인할 범위를 줄인다. 2단계 로킹은 잠금 확장 뒤 축소 단계로 나눈다.

꼭 기억할 것

관계대수 σ 선택=행, π 추출=열, ⋈ 조인, ÷ 디비전=모든 조건값과 관련된 대상.

헷갈리는 지점 잠금 단위가 커지면 관리 비용은 줄지만 동시성이 낮아지기 쉽다. 2PL이 교착상태 자체를 없애지는 않는다.

07

NoSQL과 CAP 정리

관계형 DB는 고정된 스키마와 SQL 질의를 사용한다. NoSQL은 키-값, 문서, 컬럼 패밀리, 그래프처럼 스키마가 유연한 저장 모델을 묶어 부르는 말이다. CAP 정리는 분산 시스템이 일관성(Consistency)·가용성(Availability)·분할 내성(Partition tolerance) 중 네트워크 분할 상황에서 최대 두 가지만 동시에 만족할 수 있다는 이론이다. 샤딩은 하나의 큰 데이터셋을 여러 서버에 나누어 저장하는 수평 분할이다.

꼭 기억할 것

분할 내성은 분산 환경에서 사실상 항상 고려 대상이므로, 실제로는 분할 상황에서 일관성과 가용성 중 무엇을 우선할지 선택하는 문제로 이해한다.

헷갈리는 지점 NoSQL이 트랜잭션이나 관계를 전혀 지원하지 않는다고 단정하지 않는다. 지원 범위는 제품마다 다르다.
