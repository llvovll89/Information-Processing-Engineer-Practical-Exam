SQL

눈으로 실행 계획 대신 결과 행을 추적하기

CRUD 경험을 점수로 바꾸기 좋은 영역이다. NULL, 외부 조인, 집계, 서브쿼리에서 실제로 남는 행을 직접 적어보자. 문법은 표준 중심이며 DBMS별 차이를 표시했다.

이번 단원 완료 기준

핵심 규칙을 설명하고, 연습문제의 답과 이유를 해설 없이 적을 수 있으면 체크하세요. 이해 체크와 정답 기록은 별도로 저장됩니다.

01

문장 종류와 기본 틀

DDL은 CREATE·ALTER·DROP, DML은 INSERT·UPDATE·DELETE와 조회 SELECT, DCL은 GRANT·REVOKE, TCL은 COMMIT·ROLLBACK·SAVEPOINT다. SELECT를 DQL로 별도 분류하는 교재도 있다.

꼭 기억할 것

UPDATE t SET col=값 WHERE 조건; DELETE FROM t WHERE 조건; INSERT INTO t(col) VALUES(값);

헷갈리는 지점 DROP은 객체 제거, DELETE는 행 삭제, TRUNCATE는 전체 행 제거. 롤백 가능 여부는 DBMS·트랜잭션 조건에 따라 달라 일반화 금지.

02

SELECT 논리 처리 순서

개념적으로 FROM·JOIN → WHERE → GROUP BY → HAVING → SELECT → DISTINCT → ORDER BY 순으로 결과를 구성한다. 실제 엔진의 물리 실행 순서와는 다르다.

꼭 기억할 것

WHERE는 개별 행을, HAVING은 그룹을 거른다. ORDER BY 없이는 출력 순서를 보장하지 않는다.

헷갈리는 지점 집계한 COUNT(*) 조건을 WHERE에 직접 쓰지 않는다. SELECT 별칭의 사용 가능 위치는 DBMS에 따라 차이가 있다.

03

NULL과 집계

NULL은 값이 없거나 알려지지 않은 상태다. = NULL 대신 IS NULL을 쓴다. COUNT(*)는 행 수, COUNT(col)는 NULL이 아닌 값 수, COUNT(DISTINCT col)는 중복·NULL을 제외한 수다.

꼭 기억할 것

SUM·AVG는 NULL을 제외한다. 값 10,NULL,20의 AVG는 15이다.

헷갈리는 지점 NOT IN의 비교 대상에 NULL이 있으면 UNKNOWN 때문에 기대한 행이 사라질 수 있다. NOT EXISTS와 구별한다.

04

조인과 행 개수

INNER JOIN은 매칭된 행만, LEFT JOIN은 왼쪽 전체와 매칭된 오른쪽, RIGHT JOIN은 오른쪽 전체와 매칭된 왼쪽을 남긴다. 매칭되지 않은 쪽은 NULL이다.

꼭 기억할 것

같은 키가 왼쪽 2행·오른쪽 3행이면 해당 키의 조인 결과는 6행.

헷갈리는 지점 LEFT JOIN 뒤 WHERE b.col=값을 쓰면 NULL로 채워진 행이 제거된다. ON에 조건을 넣는 것과 결과가 다르다.

05

서브쿼리와 집합 연산

IN은 결과 집합 포함 여부, EXISTS는 조건에 맞는 행의 존재 여부다. 상관 서브쿼리는 바깥 행의 값을 참조한다. UNION은 중복 제거, UNION ALL은 중복 유지다.

꼭 기억할 것

부서별 평균보다 큰 급여: e.salary > (SELECT AVG(x.salary) FROM emp x WHERE x.dept=e.dept).

헷갈리는 지점 스칼라 서브쿼리가 여러 행을 반환하면 오류가 날 수 있다. ANY·ALL과 단순 =를 구별한다.

06

제약조건과 도메인

PRIMARY KEY는 행 식별, FOREIGN KEY는 참조 일관성, UNIQUE는 유일성, NOT NULL은 값 필수, CHECK는 조건 제약이다. CREATE DOMAIN은 재사용할 값의 타입과 조건을 정의한다.

꼭 기억할 것

CREATE DOMAIN score_t AS INTEGER CHECK (VALUE BETWEEN 0 AND 100); PostgreSQL에서 지원하는 예다.

헷갈리는 지점 CHECK만으로 NULL을 항상 차단하지 않는다. 필수값에는 NOT NULL을 함께 둔다. CREATE DOMAIN은 모든 DBMS가 지원하지 않는다.

07

패턴과 뷰·인덱스

LIKE의 %는 0개 이상 문자, _는 정확히 한 문자다. 뷰는 조회문으로 정의한 논리적 테이블이다. 인덱스는 검색을 돕는 별도 구조로 저장 공간과 쓰기 비용을 사용한다.

꼭 기억할 것

LIKE '김%' / ORDER BY score DESC, id ASC / CREATE VIEW v AS SELECT ...

헷갈리는 지점 일반 뷰가 항상 결과를 물리적으로 저장하는 것은 아니다. 물리화 뷰와 구별한다.

08

CASE 조건식과 NULL 대체

CASE WHEN 조건1 THEN 값1 WHEN 조건2 THEN 값2 ELSE 기본값 END은 조건별로 다른 값을 계산하는 조건식이며, 여러 WHEN은 위에서부터 순서대로 검사해 처음 참인 조건의 값을 사용한다. COALESCE(a,b)는 a가 NULL이면 b를, 아니면 a를 반환해 NULL을 기본값으로 대체할 때 쓴다.

꼭 기억할 것

ELSE를 생략하면 어떤 WHEN도 참이 아닌 행은 NULL이 된다.

헷갈리는 지점 WHEN 조건이 겹치면 먼저 나온 조건이 우선한다. 아래쪽이 더 구체적이어도 위쪽에서 이미 참이면 아래는 검사하지 않는다.
