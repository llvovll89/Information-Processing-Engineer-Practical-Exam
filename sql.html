테이블에서 SELECT 결과 만들기

테이블은 행과 열로 구성되며 SELECT는 필요한 열을 고른다. FROM은 대상 테이블, WHERE는 행 조건이다. *는 모든 열이며 AS는 결과 열의 별칭이다. DISTINCT는 선택된 열 조합의 중복을 제거한다.

조건은 AND·OR·NOT으로 결합하며 AND가 OR보다 우선한다. BETWEEN a AND b는 양 끝을 포함한다. IN(값목록)은 그중 하나인지 검사한다. 문자열은 작은따옴표로 표시한다.

SELECT name, score AS 점수
FROM student
WHERE score BETWEEN 60 AND 100
ORDER BY score DESC, name ASC;

과정으로 이해하기

  1. 60~100점 행만 남긴다.
  2. name과 score 두 열을 출력한다.
  3. 점수 내림차순, 동점은 이름 오름차순으로 정렬한다.

답을 가리고 확인

확인 답안 보기

둘 다 포함한다.

꼭 기억할 것

헷갈리는 지점 DISTINCT 한 열의 중복과 두 열 조합의 중복은 다르다. 정렬은 ORDER BY가 있어야 보장된다.

10

INSERT·UPDATE·DELETE·DDL·권한

INSERT는 행을 넣고 UPDATE는 기존 행의 열값을 바꾸며 DELETE는 행을 지운다. WHERE가 없으면 UPDATE와 DELETE가 모든 행에 적용된다. CREATE TABLE은 구조를 만들고 ALTER TABLE은 구조를 바꾸며 DROP TABLE은 객체를 제거한다.

GRANT는 권한 부여, REVOKE는 권한 회수다. COMMIT은 트랜잭션 확정, ROLLBACK은 취소, SAVEPOINT는 부분 취소 기준을 만든다. DDL 자동 커밋과 TRUNCATE의 롤백 가능 여부는 DBMS마다 다르다.

CREATE TABLE student (
 id INTEGER PRIMARY KEY,
 name VARCHAR(20) NOT NULL,
 score INTEGER CHECK (score BETWEEN 0 AND 100)
);
INSERT INTO student(id,name,score) VALUES(1,'민수',70);
UPDATE student SET score=80 WHERE id=1;
DELETE FROM student WHERE id=1;

과정으로 이해하기

  1. 테이블 생성→한 행 추가→그 행 점수를 80으로 변경→행 삭제. 마지막에 테이블 구조는 남는다.

확인 답안 보기

11

GROUP BY·HAVING을 실제 행으로 풀기

GROUP BY는 지정한 값이 같은 행들을 묶는다. COUNT·SUM·AVG·MIN·MAX는 그룹별로 계산한다. WHERE는 그룹 만들기 전 행 필터, HAVING은 그룹 계산 후 필터다. 집계하지 않은 SELECT 열은 원칙적으로 그룹 기준과 일치해야 한다.

부서 A에 급여 10,30, 부서 B에 20인 세 행이라면 A 평균 20, B 평균 20이다. WHERE salary>=20을 먼저 적용하면 A에는 30만 남아 평균 30이 된다. 이처럼 행 필터와 그룹 필터는 결과가 다르다.

SELECT dept, COUNT(*) AS n, AVG(salary) AS avg_salary
FROM emp
GROUP BY dept
HAVING COUNT(*) >= 2
ORDER BY dept;
GROUP BY·HAVING을 실제 행으로 풀기 · 한눈에 비교
부서급여 목록COUNT(*)AVG
A10,30220
B20120

과정으로 이해하기

  1. 입력 A10,A30,B20을 부서로 묶으면 A 2행, B 1행.
  2. HAVING에서 B 제거. 출력 A,2,20.

답을 가리고 확인

집계 결과가 3 이상인 그룹을 남기는 절은?

확인 답안 보기

HAVING. WHERE에 COUNT(*)>=3을 직접 쓰지 않는다.

꼭 기억할 것

행 나열 → WHERE 제거 → 그룹 묶기 → 집계 → HAVING → 출력·정렬.

헷갈리는 지점 COUNT(*)는 모든 행, COUNT(col)는 NULL 제외. AVG 분모도 NULL 아닌 값 개수.

12

NULL의 3값 논리와 NOT IN

SQL 조건은 TRUE·FALSE 외에 UNKNOWN을 가질 수 있다. NULL=값과 NULL<>값은 UNKNOWN이고 WHERE는 TRUE인 행만 통과시킨다. IS NULL·IS NOT NULL은 NULL 여부를 검사한다. COALESCE(a,0)는 첫 NULL 아닌 값을 선택한다.

2 NOT IN (1,NULL)은 2<>1 AND 2<>NULL이어서 TRUE AND UNKNOWN → UNKNOWN이다. 따라서 통과하지 않는다. NULL이 섞인 부정 포함 조건은 상관 NOT EXISTS로 의도를 표현할 수 있다.

SELECT id FROM A
WHERE NOT EXISTS (
 SELECT 1 FROM B WHERE B.aid=A.id
)
ORDER BY id;

과정으로 이해하기

  1. A가 1,2이고 B가 1,NULL이면 id=1은 매칭 존재로 제외, id=2는 매칭 없으므로 남는다.

답을 가리고 확인

10,NULL,20의 SUM·AVG·COUNT(col)는?

확인 답안 보기

꼭 기억할 것

NULL은 0도 빈 문자열도 아니다. UNKNOWN은 WHERE에서 남지 않는다.

헷갈리는 지점 NOT UNKNOWN도 UNKNOWN이다. NULL이 있으면 모든 행이 무조건 사라진다는 식의 설명도 피한다.

13

조인의 곱셈·ON과 WHERE·셀프 조인

조인은 두 테이블 행을 조건으로 연결한다. 같은 키가 A에 2행, B에 3행이면 각각 모두 매칭되어 6행이다. CROSS JOIN은 모든 조합이며 A m행, B n행이면 m×n행이다. SELF JOIN은 같은 테이블에 서로 다른 별칭을 붙여 자기 자신과 연결한다.

LEFT JOIN의 ON은 매칭 조건이고 WHERE는 만들어진 결과 필터다. ON에 오른쪽 조건을 붙이면 매칭 실패한 왼쪽 행도 NULL로 남지만 WHERE의 오른쪽 열 조건은 그 행을 제거할 수 있다.

SELECT a.id, b.status
FROM A a LEFT JOIN B b
 ON a.id=b.aid AND b.status='Y'
ORDER BY a.id;

과정으로 이해하기

  1. A id=1,2 / B=(1,Y),(2,N)이면 1,Y와 2,NULL.
  2. b.status=Y를 WHERE에 두면 2,NULL도 제거되어 1,Y만 남는다.

조인은 키별로 매칭 행들을 나열하고 미매칭 행을 따로 추가한다.

헷갈리는 지점 외래키 관계라고 결과가 항상 한 행씩인 것은 아니다. 일대다·중복 키를 확인한다.

14

ANY·ALL·EXISTS·집합 연산

x > ANY(집합)는 하나 이상의 값보다 크면 참이고 x > ALL(집합)는 모든 값보다 커야 참이다. NULL 없는 비어 있지 않은 집합 10,20,30에서는 >ANY는 최솟값 10보다 큰지, >ALL은 최댓값 30보다 큰지로 확인할 수 있다.

EXISTS는 서브쿼리 결과 행의 존재를 검사한다. UNION은 합친 뒤 중복 제거, UNION ALL은 중복 유지, INTERSECT는 공통 행, EXCEPT는 왼쪽에만 있는 행이다. Oracle 전통 문법은 차집합에 MINUS를 사용한다. 입력 열 수와 대응 자료형의 호환성이 필요하다.

과정으로 이해하기

  1. 25 > ANY(10,20,30)은 참: 10·20보다 크다.
  2. 25 > ALL(10,20,30)은 거짓: 30보다 작다.

UNION과 UNION ALL에서 중복 행을 유지하는 것은?

확인 답안 보기

UNION ALL.

꼭 기억할 것

>ANY: 하나만 만족 / >ALL: 모두 만족. NULL·빈 집합은 별도로 해석한다.

헷갈리는 지점 빈 집합에 대한 ALL은 참, ANY는 거짓. MIN/MAX 치환을 무조건 적용하지 않는다.

15

윈도 함수·순위·뷰·인덱스

윈도 함수는 행을 유지하면서 그룹별 계산을 덧붙인다. OVER(PARTITION BY dept ORDER BY score DESC)는 부서별로 나눠 점수 순서로 계산한다. ROW_NUMBER는 행별 번호, RANK는 동점 같은 순위와 다음 순위 건너뜀, DENSE_RANK는 동점 뒤 순위를 이어간다.

일반 뷰는 SELECT 정의를 저장하는 논리적 테이블이며 복잡한 질의를 단순화하고 노출 열을 제한한다. 인덱스는 검색 경로를 돕지만 저장 공간·쓰기 비용이 추가된다. 뷰의 갱신 가능 여부는 정의와 DBMS에 따라 다르다.

SELECT id, score,
 RANK() OVER (ORDER BY score DESC) AS r,
 DENSE_RANK() OVER (ORDER BY score DESC) AS dr
FROM student
ORDER BY score DESC, id;
