문장·결정·조건·MC/DC를 표로 확인

문장 커버리지는 전체 실행문 중 실행한 비율이고 결정 커버리지는 각 판정의 참·거짓 결과를 모두 실행했는지다. 조건 커버리지는 판정 안 개별 조건이 참·거짓을 모두 경험했는지다. 둘 중 하나를 만족했다고 다른 기준을 자동 만족하지 않는다.

MC/DC는 다른 조건을 고정한 상태에서 한 조건만 바뀌어 판정 결과도 바뀌는 쌍을 찾는다. A AND B에는 (T,T),(F,T),(T,F)가 전형적인 논리 조합이다. 실제 코드의 단락 평가 여부는 별도로 확인한다.

순환 복잡도·테스트 수준·통합 순서

단위는 모듈 하나, 통합은 모듈 간 연결, 시스템은 전체 시스템, 인수는 사용자 요구 충족을 검사한다. 하향식에서 아직 없는 하위를 스텁, 상향식에서 아직 없는 상위 호출자를 드라이버로 대체한다.

과정으로 이해하기

  1. N=6, E=7의 단일 연결 그래프: V=7-6+2=3.
  2. 단순 if 두 개도 결정 수 2+1=3.

11

정적·동적 테스트와 결함 관리

정적 테스트는 프로그램을 실행하지 않고 산출물·코드를 검토한다. 동료 검토는 동료가 확인, 워크스루는 작성자가 설명하며 검토, 인스펙션은 역할·절차에 따른 공식 검토다. 정적 분석 도구는 잠재 결함·규칙 위반 등을 탐지한다.

동적 테스트는 실행 결과를 검사한다. 오류는 사람의 실수, 결함은 산출물에 들어간 문제, 장애는 실행 중 기대 서비스에서 벗어난 현상으로 구별한다. 결함의 심각도는 영향, 우선순위는 수정 순서다.

과정으로 이해하기

  1. 검토로 0 나눗셈 가능성을 찾음 → 정적.

성능 테스트·오라클·품질

부하 테스트는 예상 부하에서 성능, 스트레스는 한계를 넘는 부하에서 반응, 스파이크는 급격한 부하 변화, 지속(내구성) 테스트는 장시간 실행에서 누수·성능 저하를 확인한다. 처리량은 단위 시간 처리 수, 응답시간은 요청부터 응답까지 시간이다.

오라클은 결과의 정당성을 판정하는 기준이다. 참 오라클은 모든 입력에 정답 판단, 샘플링은 일부 입력, 휴리스틱은 일부 판단과 추정, 일관성 검사는 과거·다른 시스템 결과와 비교한다. 수정·적응·완전·예방 유지보수는 변경 목적을 구별한다.

과정으로 이해하기

  1. 새 OS를 지원하도록 수정 → 적응 유지보수.
  2. 장시간 부하에서 메모리 증가 확인 → 지속 테스트.
