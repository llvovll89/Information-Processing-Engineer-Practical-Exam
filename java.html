Java

참조 타입과 실제 객체 타입을 구분하기

JavaScript와 이름·문법 일부가 비슷해도 Java는 정적 타입 언어다. 출력 문제에서는 필드, 오버라이딩, 오버로딩, 생성자, static을 분리하면 복잡한 코드도 따라갈 수 있다.

이번 단원 완료 기준

핵심 규칙을 설명하고, 연습문제의 답과 이유를 해설 없이 적을 수 있으면 체크하세요. 이해 체크와 정답 기록은 별도로 저장됩니다.

01

실행 뼈대와 타입

클래스 안에 메서드를 정의하고 main에서 시작한다. int와 boolean 같은 기본형은 값, 배열·String·객체 변수는 참조값을 저장한다. 지역변수는 사용 전 초기화가 필요하다. 필드는 타입에 따른 기본값을 갖는다.

class Main {
 public static void main(String[] args) {
  int n=7;
  System.out.println(n/2);
 }
}
꼭 기억할 것

정수 나눗셈은 0 방향 절삭. boolean에 0이나 1을 직접 넣지 않는다.

헷갈리는 지점 Java의 조건식은 boolean이어야 한다. C처럼 if(1)을 쓰지 않는다.

02

==와 equals

기본형 ==는 값을 비교하지만 참조형 ==는 같은 객체인지 비교한다. String의 equals는 문자열 내용을 비교한다. 일반 객체의 equals는 구현에 따라 다르며 Object 기본 구현은 동일성을 비교한다.

꼭 기억할 것

new String("OK") 두 개는 내용이 같아도 별도 객체다. 배열 내용 비교에는 Arrays.equals를 사용한다.

헷갈리는 지점 문자열 리터럴 풀 때문에 "OK" == "OK"가 true인 사례를 모든 문자열에 일반화하지 않는다.

03

필드 접근과 오버라이딩

부모 변수 p가 자식 객체를 참조할 수 있다. p.x 같은 필드는 변수의 선언 타입을 따라 찾는다. 재정의한 인스턴스 메서드 p.f()는 실제 객체 타입을 따라 호출한다.

꼭 기억할 것

Parent p = new Child(); → 필드는 Parent, override 메서드는 Child.

헷갈리는 지점 static 메서드는 오버라이딩이 아니라 숨김이다. private 메서드도 일반적인 동적 오버라이딩 대상으로 다루지 않는다.

04

오버로딩과 형 변환

오버로딩은 메서드 이름이 같고 매개변수 목록이 다른 것이다. 호출할 시그니처는 컴파일 시 인자의 선언 타입으로 정한다. 그 후 해당 시그니처의 오버라이딩은 실제 객체를 따른다.

꼭 기억할 것

반환 타입만 다르게 해서는 오버로딩이 되지 않는다.

헷갈리는 지점 Object x="a";를 f(x)에 넣으면 f(String)이 아니라 f(Object)가 선택된다.

05

생성자와 초기화

new Child()를 하면 부모 부분부터 초기화된다. 생성자는 반환 타입이 없고 클래스 이름과 같다. this(...)는 같은 클래스 생성자, super(...)는 부모 생성자 호출이다. Java 21 기준 명시적 생성자 호출은 생성자의 첫 문장이다.

꼭 기억할 것

정적 초기화는 클래스 초기화 시 한 번. 인스턴스 필드 초기화와 생성자는 객체마다 수행한다.

헷갈리는 지점 부모 생성자에서 재정의된 메서드를 호출하면 자식 필드의 명시적 초기화 전 기본값을 볼 수 있다. 호출 순서를 적는다.

06

static·매개변수·배열

static 필드는 클래스 수준에서 공유된다. 인스턴스 필드는 객체마다 존재한다. Java도 값 전달이며 객체를 넘기면 참조값을 복사한다. 배열 원소 변경은 공유 객체를 바꾸지만 매개변수에 새 배열을 대입하는 것은 호출자 변수를 바꾸지 않는다.

꼭 기억할 것

배열 길이는 a.length, 문자열 길이는 s.length().

헷갈리는 지점 향상된 for에서 기본형 변수 x에 대입해도 원래 배열 원소가 바뀌지 않는다.

07

문자열 +와 예외

+는 왼쪽부터 평가한다. 앞이 숫자면 산술, 문자열이 등장하면 뒤를 문자열로 이어 붙인다. try에서 예외가 나면 나머지 문장을 건너뛰고 맞는 catch, 이어서 finally를 실행한다.

꼭 기억할 것

print는 줄바꿈 없음, println은 끝에 줄바꿈. finally는 정상 반환·예외 경로에서도 보통 실행된다.

헷갈리는 지점 finally에서 return을 쓰면 try의 반환을 덮을 수 있다. 시험 추적용 함정이며 실무에서 피할 패턴이다.

08

추상 클래스·인터페이스·제네릭

추상 클래스는 공통 상태와 구현, 미구현 메서드를 둘 수 있다. 인터페이스는 역할의 계약이다. 클래스 상속은 하나, 인터페이스 구현은 여러 개 가능하다. List<Integer> 같은 제네릭은 원소 타입을 제한한다.

꼭 기억할 것

extends / implements / abstract / final을 구별한다. final 변수는 재대입 불가다.

헷갈리는 지점 final 배열의 원소는 수정할 수 있다. 배열 변수가 다른 배열을 가리키도록 바꾸는 것이 금지된다.
