조건 ? 참일때값 : 거짓일때값은 조건에 따라 한쪽 값만 선택한다. Java는 피연산자를 왼쪽부터 평가한다. +에서 문자열이 등장한 뒤에는 문자열 결합이므로 괄호를 보고 숫자 계산이 끝나는 위치를 정한다.

int x=2;
int y=x++ + ++x;
System.out.print(x+" "+y+" "+(x%2==0 ? "E" : "O"));

12

접근 제어·this·super·final

public은 넓은 접근을 허용하고 private은 선언한 클래스 내부 접근을 제한한다. 접근 지정자를 생략하면 같은 패키지에서 접근할 수 있다. protected는 같은 패키지와 상속 관계에서 조건에 따라 접근을 허용한다. this는 현재 객체, super는 부모 클래스 부분을 지정할 때 쓴다.

final 변수는 재대입할 수 없고 final 메서드는 오버라이딩할 수 없으며 final 클래스는 상속할 수 없다. final 객체 참조가 고정되어도 객체 내부 상태가 항상 불변인 것은 아니다.

final int[] a={1,2};
a[0]=9;
System.out.print(a[0]);
// a=new int[]{3}; 는 컴파일 오류

과정으로 이해하기

  1. 배열 참조 a는 고정되지만 배열 원소는 바꿀 수 있어 9 출력.

답을 가리고 확인

final 클래스에 extends를 사용하면?

확인 답안 보기

상속할 수 없어 컴파일 오류.

꼭 기억할 것

this.x는 현재 객체 필드, super.x는 부모 필드. static 문맥에는 현재 객체 this가 없다.

헷갈리는 지점 protected를 “어느 위치의 자식 객체든 접근 가능”으로 일반화하지 않는다. 패키지 밖 규칙이 더 제한적이다.

13

업캐스팅·다운캐스팅·다형성

Parent p=new Child();는 자식 객체를 부모 타입 참조로 다루는 업캐스팅이다. 실제 객체는 Child로 유지된다. 부모 타입에 선언되지 않은 자식 전용 메서드를 p로 바로 호출할 수는 없다.

(Child)p는 다운캐스팅이다. 실제 객체가 Child에 해당하면 가능하지만 실제 Parent 객체를 Child로 바꾸어 만들어 주지는 않는다. 호환되지 않으면 ClassCastException이다. instanceof로 타입 적합 여부를 검사할 수 있다.

과정으로 이해하기

  1. Parent p=new Child()에서 p는 부모형 참조, 대상 객체는 자식.
  2. p.f()가 오버라이딩된 인스턴스 메서드라면 자식 구현 실행.
  3. Parent p=new Parent(); (Child)p는 실행 중 예외.

답을 가리고 확인

오버로딩 선택은 실제 객체 타입으로 하는가?

확인 답안 보기

아니다. 인자의 컴파일 시 타입으로 시그니처를 정하고, 해당 인스턴스 메서드의 오버라이딩은 실제 객체 타입으로 정한다.

꼭 기억할 것

필드·static 선택은 선언 타입, 오버라이딩된 인스턴스 메서드는 실제 객체 타입.

헷갈리는 지점 캐스팅은 객체의 종류를 변환·재생성하는 작업이 아니다.

14

String 메서드와 StringBuilder

String은 불변이므로 substring·replace·toUpperCase는 결과를 새 문자열로 반환한다. substring(start,end)는 end를 제외한다. charAt(i)는 char 하나, indexOf는 처음 찾은 위치 또는 -1이다.

StringBuilder는 내부 문자 내용을 수정할 수 있다. append는 끝에 추가하고 reverse는 뒤집는다. String의 equals는 내용 비교, ==는 참조 비교다. 문자열 리터럴 풀은 일부 == 결과에 영향을 주지만 일반 내용 비교 규칙을 대체하지 않는다.

String s="abc";
s.toUpperCase();
StringBuilder b=new StringBuilder(s);
b.append("d").reverse();
System.out.print(s+" "+b);

과정으로 이해하기

  1. s는 결과를 재대입하지 않아 abc. b는 abcd를 만든 뒤 dcba로 수정. 출력 abc dcba.

답을 가리고 확인

"JAVA".indexOf("X")는?

확인 답안 보기

-1. 찾지 못한 경우.

꼭 기억할 것

"ABCDE".substring(1,4) → "BCD". charAt(0) → 'A'.

헷갈리는 지점 String의 length()와 배열의 length를 혼동하지 않는다.

15

예외의 전달·catch 순서·finally

try의 실행 중 예외가 생기면 그 지점 뒤 문장을 건너뛰고 대응하는 catch로 이동한다. catch가 없으면 호출자에게 전달된다. throws는 예외 발생 가능성 선언, throw는 실제 예외를 던지는 문장이다.

catch는 위에서 아래로 검사하므로 하위 타입을 먼저 둔다. 상위 Exception을 먼저 두고 뒤에 하위 예외 catch를 두면 도달할 수 없어 컴파일 오류다. finally는 정상 종료·반환·예외 경로에서 보통 실행되지만 JVM 강제 종료 같은 경우까지 보장하지 않는다.

과정으로 이해하기

  1. try에서 A 출력 후 예외 → B는 건너뜀.
  2. catch가 C 출력, finally가 D 출력, 이후 E 출력이라면 ACDE.

답을 가리고 확인

throw와 throws의 차이는?

확인 답안 보기

throw는 예외를 던짐, throws는 메서드 선언에서 발생 가능한 예외를 알림.

꼭 기억할 것

출력 순서는 try에서 실행한 부분 → 맞는 catch → finally → 이어지는 코드.

헷갈리는 지점 finally에서 return하면 앞의 반환·예외를 덮을 수 있다. 반환값을 확정한 시점과 finally의 부수효과를 구별한다.

16

컬렉션·제네릭·박싱

List는 순서와 중복을 허용하고 Set은 중복을 배제하며 Map은 키와 값의 대응이다. ArrayList는 배열 기반, LinkedList는 연결 구조 기반이다. HashSet의 순서는 보장하지 않으며 TreeSet은 정렬된 순서다. Map의 같은 키에 put하면 기존 값을 바꾼다.

제네릭 List<Integer>는 원소 타입을 제한한다. 기본형 int를 제네릭 인자로 직접 쓰지 않고 포장 클래스 Integer를 사용한다. int와 Integer 사이의 자동 변환은 박싱·언박싱이다. null을 int로 언박싱하면 NullPointerException이다.

java.util.List<Integer> a=new java.util.ArrayList<>();
a.add(10); a.add(20); a.add(10);
a.remove(1);
System.out.print(a);

과정으로 이해하기

  1. 위치 1의 20을 삭제해 [10, 10]. 값 1을 지우는 코드가 아니다.

답을 가리고 확인

List<int>를 쓸 수 있는가?

확인 답안 보기

없다. List<Integer>를 사용한다.

꼭 기억할 것

List remove(int)는 위치 삭제, remove(Object)는 값 삭제.

헷갈리는 지점 Integer 참조의 == 결과를 작은 값 캐싱에 기대 암기하지 않는다.
