최근 기출 주제만으로 범위를 좁히면 낯선 단답형에 취약해진다. 공식 출제경향의 통합·인터페이스·서버·패키징 영역을 보완한다. 이 장의 항목 모두가 특정 회차에 나왔다는 뜻은 아니다.

이번 단원 완료 기준

핵심 규칙을 설명하고, 연습문제의 답과 이유를 해설 없이 적을 수 있으면 체크하세요. 이해 체크와 정답 기록은 별도로 저장됩니다.

01

연계와 인터페이스

EAI는 기업 내부 애플리케이션 통합, ESB는 공통 버스를 중심으로 서비스 연계, SOA는 서비스를 단위로 구성하는 아키텍처다. Point-to-Point는 직접 연결, Hub-and-Spoke는 중앙 허브를 통한다.

꼭 기억할 것

JSON은 데이터 교환 형식, XML은 태그 기반 구조, SOAP는 XML 기반 메시지 프로토콜, REST는 자원 중심 제약의 아키텍처 스타일.

헷갈리는 지점 REST를 JSON 형식의 다른 이름으로 쓰지 않는다. HTTP API라고 모두 REST 제약을 충족하는 것도 아니다.

02

미들웨어와 트랜잭션 연계

미들웨어는 응용과 기반 환경 사이 공통 통신·실행 기능을 제공한다. RPC는 원격 함수를 호출하는 추상화, MOM은 메시지 기반 비동기 통신, TP 모니터는 트랜잭션 처리 관리다.

꼭 기억할 것

동기는 응답 대기, 비동기는 요청과 결과 처리를 분리. 송수신 전문의 헤더·데이터·종료 구조와 오류 처리를 구분한다.

헷갈리는 지점 비동기라고 처리 성공이 보장되지 않는다. 재시도·중복 처리·순서 정책을 설계해야 한다.

03

형상 관리와 배포

형상 식별→변경 통제→상태 보고→감사의 흐름으로 버전과 변경을 관리한다. 기준선은 공식 검토·승인된 기준 상태다. CI는 빈번한 통합과 자동 검증, CD는 전달/배포 자동화를 뜻한다.

꼭 기억할 것

Git commit은 로컬 이력, push는 원격 반영. 릴리스 노트는 변경·수정·알려진 문제·영향을 전달한다.

헷갈리는 지점 버전 관리 도구를 쓰는 것만으로 변경 승인·감사까지 포함하는 형상 관리 전체를 수행한 것은 아니다.

04

패키징과 문서·DRM

패키징은 실행·설치에 필요한 구성물을 묶어 전달하는 작업이다. 사용자 매뉴얼과 설치 매뉴얼의 대상·절차를 구분한다. DRM은 콘텐츠 사용 권한을 통제한다.

꼭 기억할 것

DRM 구성: 콘텐츠 제공자, 배포자, 클리어링 하우스, 소비자, 패키저, 컨트롤러 등을 역할로 이해한다.

헷갈리는 지점 릴리스 노트는 기능 변경 안내이며 설치 절차 전체를 대신하지 않는다.

05

추가 단답 점검

SOAP·WSDL·UDDI는 메시지·서비스 기술·서비스 등록/탐색이라는 서로 다른 역할이다. ETL은 추출·변환·적재, EAI는 시스템 간 연계다. 백업의 RPO는 감내 가능한 데이터 손실 시점, RTO는 복구 목표 시간이다.

꼭 기억할 것

Full 백업 전체 / Incremental 직전 백업 이후 / Differential 마지막 전체 백업 이후 변경분.

헷갈리는 지점 증분 복구에는 전체 백업과 이후 필요한 증분 체인이 필요하다. 차등은 마지막 전체와 마지막 차등이 핵심이다.

직접 풀어보기 4문제

모두 유형 연습을 위해 직접 만든 문제입니다. C 예제의 printf·strlen은 필요한 표준 헤더가 포함된 상황을 가정합니다. Java는 표시된 클래스·main 위치에서 실행합니다. 단답은 동의어가 있을 수 있어 자동 판정 대신 자기 채점을 사용합니다.
