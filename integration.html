EAI 유형·ESB·연계 흐름

연계는 송신 시스템에서 데이터를 추출하고 변환해 수신 시스템에 전달·검증·반영하는 과정이다. EAI는 기업 내 응용 통합이고 Point-to-Point는 개별 연결, Hub-and-Spoke는 중앙 허브, Message Bus는 공통 버스 중심 구조다.

ESB는 서비스 메시지 라우팅·변환 등 공통 연계를 제공한다. 전문은 통신 규약에 맞춘 메시지로 헤더·데이터·종료 부분 등을 구분한다. 장애 시 재시도·중복·순서·오류 응답 정책을 정해야 한다.

  2. 주문번호·이벤트번호 등으로 이미 처리한 메시지를 식별해 중복 효과를 막는다.

08

REST·HTTP·SOAP·WSDL·UDDI

REST는 자원 중심 인터페이스·무상태 등 제약을 가진 아키텍처 스타일이다. HTTP GET은 조회, POST는 처리·생성 등에 사용, PUT은 대상 자원 대체, PATCH는 부분 변경, DELETE는 삭제에 사용한다. GET 같은 안전 메서드는 서버 상태 변경을 요청하는 의미가 아니다.

SOAP는 XML 기반 메시징 프로토콜, WSDL은 서비스 동작·메시지·접속 정보 기술, UDDI는 서비스 등록·탐색 역할이다. JSON은 키·값·배열 등을 표현하는 데이터 형식이며 XML은 태그 기반 구조다. 형식과 통신 규칙과 설계 스타일을 구분한다.

09

미들웨어·DB 연결·서버 흐름

미들웨어는 응용과 OS·통신·데이터 환경 사이의 공통 기능을 제공한다. RPC는 원격 호출 추상화, MOM은 메시지 지향 통신, ORB는 분산 객체 요청 중개, TP 모니터는 트랜잭션 처리 관리, WAS는 서버 응용 실행 환경을 제공한다.

DB 연결에서는 연결 생성→SQL 준비·바인딩→실행→결과 읽기→자원 정리 순서를 이해한다. 연결 풀은 연결을 재사용해 생성 비용을 줄인다. 서버는 입력 검증·업무 규칙·트랜잭션·예외 처리·인가를 책임별로 나눠 구현한다.

과정으로 이해하기

  1. 요청 입력 검사→사용자 권한 확인→업무 서비스→DB 트랜잭션→응답.
  2. DB 실패 시 성공 응답을 보내지 않고 오류·롤백 정책을 적용한다.

10

형상 관리·빌드·배포 전략

형상 관리는 구성 항목을 식별하고 변경을 통제하며 상태를 기록·감사한다. 기준선은 검토·승인되어 변경 관리 기준이 된 상태다. 빌드는 소스에서 실행·배포 산출물을 만드는 과정이고 배포는 그 결과를 대상 환경에 반영하는 과정이다.

CI는 자주 통합해 자동 빌드·테스트로 문제를 찾고 Continuous Delivery는 배포 가능한 상태를 유지하며 Continuous Deployment는 변경을 자동으로 운영에 배포한다. Blue-Green은 두 환경 전환, Canary는 일부 사용자·트래픽에 먼저 배포, Rolling은 순차 교체다.

과정으로 이해하기

  1. 신버전을 트래픽 5%에 먼저 적용→지표 확인→확대는 Canary.
  2. 동일 규모 새 환경 검증 후 트래픽 일괄 전환은 Blue-Green.

11

백업·복구·RPO·RTO·패키징·DRM

전체 백업은 모든 대상, 증분은 직전 백업 이후 변경, 차등은 마지막 전체 백업 이후 변경이다. 월 전체·화 증분·수 증분이라면 수요일까지 복구하려면 전체와 이후 증분 체인을 사용한다. 차등은 전체와 원하는 시점의 차등을 사용한다.

RPO는 감내 가능한 데이터 손실 기간, RTO는 복구 목표 시간이다. 패키징은 실행·설치 구성물을 전달 형태로 묶고 릴리스 노트는 변경·수정·알려진 문제를 알린다. DRM은 패키저가 보호 형태로 포장, 컨트롤러가 사용 권한 통제, 클리어링 하우스가 라이선스·권한 관리를 맡는 역할을 구분한다.

과정으로 이해하기

  1. RPO 1시간: 장애 직전 1시간 이내 데이터 손실을 감내하는 목표.
  2. RTO 2시간: 장애 이후 2시간 이내 서비스 복구 목표.

RPO 데이터 손실 허용 / RTO 복구 소요 목표. 증분 직전 이후, 차등 전체 이후.

헷갈리는 지점 백업 파일이 있다고 복구가 검증된 것은 아니다. 복구 절차·자원·시간까지 확인한다.
