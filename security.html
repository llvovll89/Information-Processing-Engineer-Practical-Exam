기밀성·무결성·가용성과 인증·인가

기밀성은 허가 없는 열람을 막고 무결성은 허가 없는 변경을 막거나 탐지하며 가용성은 필요할 때 서비스를 사용할 수 있게 하는 것이다. 개인정보 유출은 기밀성, 거래 내역 변조는 무결성, 서비스 마비는 가용성의 전형적인 사례다.

인증은 누구인지 확인, 인가는 그 주체가 어떤 자원을 사용할 수 있는지 결정한다. 다중요소 인증은 지식(암호)·소유(토큰)·생체 같은 서로 다른 요소를 결합한다. 비밀번호 두 개는 모두 지식 요소라 두 요소 인증과 다르다.

  1. 사용자 A 로그인 성공 → 인증.
  2. A가 B의 주문 id를 요청할 때 소유권 확인 → 인가.

대칭키·공개키·해시·서명·인증서

접근통제 모델·Bell-LaPadula·Biba

DAC는 소유자의 재량으로 권한을 부여하고 MAC는 보안 등급·정책을 강제한다. RBAC는 역할, ABAC는 주체·자원·환경 등의 속성으로 결정한다. 최소 권한은 업무에 필요한 권한만 주는 원칙이다.

Bell-LaPadula는 기밀성 중심으로 상위 등급 읽기 금지(No Read Up), 하위 등급 쓰기 금지(No Write Down)를 기억한다. Biba의 엄격 무결성 모델은 무결성 중심으로 하위 등급 읽기 금지(No Read Down), 상위 등급 쓰기 금지(No Write Up)를 다룬다.

과정으로 이해하기

  1. BLP: 높은 기밀 자료를 읽거나 높은 기밀 자료를 낮은 곳에 흘려 쓰는 것을 막는다.
  2. Biba: 낮은 신뢰 자료가 높은 신뢰 자료를 오염시키는 것을 막는다.

확인 답안 보기

꼭 기억할 것

BLP 기밀성: 상위 읽기·하위 쓰기 금지 / Biba 무결성: 하위 읽기·상위 쓰기 금지.

헷갈리는 지점 보안 등급과 무결성 등급의 뜻을 구별한다. Biba의 모든 변형이 같은 규칙은 아니다.

12

공격 단서로 XSS·CSRF·SQLi·SSRF 구별

XSS는 공격자 스크립트가 피해자 브라우저의 신뢰 문맥에서 실행되는 공격이다. 저장형은 게시물 등에 저장, 반사형은 요청 입력이 응답에 반사, DOM 기반은 클라이언트 처리에서 발생한다. CSRF는 로그인 상태를 악용해 의도하지 않은 요청을 보내게 한다.

SQLi는 데이터 입력이 SQL 명령 구조로 해석되는 문제이고 SSRF는 서버를 시켜 내부·외부 주소에 요청하게 한다. 경로 탐색은 ../ 등으로 허용 범위를 벗어난 파일 접근을 노린다. 대응은 각 신뢰 경계에 맞춰 적용한다.

과정으로 이해하기

  1. 댓글의 스크립트가 다른 사용자에게 실행 → 저장형 XSS.
  2. 외부 페이지가 로그인 쿠키를 이용해 송금 요청 유도 → CSRF.
  3. URL 미리보기 서버에 내부 관리 주소 입력 → SSRF.

개발 보안·TOCTOU·장비·관리
